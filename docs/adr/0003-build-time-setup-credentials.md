# ADR 0003: Build-time setup credentials instead of an open setup AP

- Status: Accepted
- Date: 2026-10-23

## Context

Upstream boots with an open AP (`ESP32_NAT_Router`, no passphrase) and an
unauthenticated web UI listening on every interface. Anyone in radio range can
join during setup, or after any factory reset, and take over the device.
Requirements: no open permanent AP, no hard-coded shared admin password, no
secrets in version control or logs.

Alternatives considered:

1. **Pre-provisioned NVS partition** generated locally with ESP-IDF's
   `nvs_partition_gen.py`. Keeps secrets out of the app image, but a factory
   reset erases NVS and returns to the open upstream defaults.
2. **Random password generated on first boot and printed on the serial
   console.** No build input needed, but it prints a password to a log, which
   the requirements forbid, and the password is lost if nobody is watching.
3. **Build-time values compiled into the image** (chosen).

## Decision

Patch 0001 adds Kconfig strings `REPEATER_SETUP_AP_SSID`,
`REPEATER_SETUP_AP_PASSWORD` and `REPEATER_ADMIN_PASSWORD`, supplied from the
git-ignored `config/secrets.local` (generated by `repeater.py init-secrets` or
copied from `config/secrets.example`).

- The AP defaults use them whenever NVS holds no AP settings.
- On a boot where the `web_password` key has never been written, the admin
  password is stored as a salted SHA-256 hash. An empty string stored later
  by the owner counts as "written", so disabling the password is respected.
- `_Static_assert` in C and `validate_secrets()` in the build tool both reject
  missing, placeholder or out-of-range values, so an unconfigured build cannot
  produce an open device.
- The admin password must differ from the AP password and fit the 128-byte
  URL-encoded login field.

## Consequences

- Secure from the first second of the first boot and after every factory
  reset.
- Each owner chooses their own credentials; nothing shared is hard-coded.
- The firmware image contains the setup passphrase and admin password.
  Release images are written next to a `PRIVATE-DO-NOT-SHARE.txt` notice and
  `build/` is git-ignored. Anyone with the image or physical flash access can
  recover them; NVS already holds Wi-Fi credentials in plaintext upstream, so
  physical access was never a protected boundary.
- CI generates throwaway random credentials to compile.

## Addendum (2026-10-23): optional uplink and AP address

Owners asked to put the existing Wi-Fi's name and password in the same file
instead of typing them into the web UI after flashing. Patch 0005 adds the
optional keys `REPEATER_UPLINK_SSID`, `REPEATER_UPLINK_PASSWORD` and
`REPEATER_AP_IP` with the same model: they apply only when NVS holds no
value, values saved at runtime win, and a factory reset restores them. The
uplink password then also lives in the firmware image, which strengthens the
existing rule that `build/` output is private. Leaving the keys out keeps the
original behaviour (choose the uplink on the Getting Started page).
